# 代码导读

LocalRDP 的代码地图：目录职责、包边界、进程链路、改动前必读的坑。路径一律相对仓库根。
用法见 [使用说明.md](使用说明.md)，工程约定见 [../AGENTS.md](../AGENTS.md)。

## 目录

```text
LocalRDP-go/
├── main.go                  入口，一行 os.Exit(rdp.Run(os.Args))
├── mygo.json                exe 的名字、版本、图标、产物目录：mygo 的打包配置
├── Scripts/build.ps1        构建：mygo 打包 + -X 注入 + 版本对账（发版带 -Version 时再压 zip）
├── internal/
│   ├── rdp/                 命令行 + RDP 宿主（package rdp，最大的一个包）
│   ├── app/                 窗口逻辑：动作、子进程、状态
│   ├── ui/                  只画 State：窗口、表单、会话页、主题、图标
│   ├── store/               设置、DPAPI 密码（叶子包）
│   ├── i18n/                语言选择：显示中文还是英文
│   ├── win32/               app 与 rdp 共用的 Win32 小工具
│   └── mcp/                 MCP 协议层（JSON-RPC 2.0 over stdio）
├── tools/                   genicon（画图标 + 图标新鲜度测试）、barpreview（预览顶栏）
├── winres/                  localrdp.png（图标源，mygo 缩成各档尺寸）+ -session.png（会话窗口那张，go:embed）
├── locales/                 en.json / zh-Hans.json 的消息 + catalog_gen.go（`go tool mygo generate` 生成）
├── docs/                    使用说明 / 手动授予特权 / 故障代码 / 代码导读（本文件）
└── .github/workflows/ci.yml windows-latest：vet / gofmt / test / build
```

## 一览

| 包 | 定位 | 关键文件 |
| --- | --- | --- |
| `internal/rdp` | 命令行与 RDP 宿主：解析参数、建无边框宿主窗口、嵌 `mstscax.dll`、把进程塞进子会话 | `run.go` `host.go` `ax.go` `rdp.go` `session_launch.go` |
| `internal/app` | 窗口侧逻辑：按钮动作、子进程管理、状态刷新、读 `command.txt` | `actions.go` `child.go` `status.go` `commands.go` |
| `internal/ui` | 只读 `State` 画界面，点击只调 `Actions`，不碰进程 | `window.go` `form.go` `session.go` `dialogs.go` `theme.go` |
| `internal/store` | 设置与 DPAPI 加密密码，不依赖其它内部包 | `config.go` `secret_windows.go` |
| `internal/i18n` | 语言选择：`Set`/`Lang`/`Locale` 说到底说哪门语言，文案本身不在这里 | `i18n.go` |
| `internal/fault` | 已知故障的代码与一句话：`E###` + `docs/故障代码.md` 的锚点，不依赖其它内部包 | `fault.go` |
| `locales` | 界面消息：`en.json` 是源，`zh-Hans.json` 是中文；`catalog_gen.go` 由 `go tool mygo generate` 从它们生成，一个 key 一个 accessor | `en.json` `zh-Hans.json` |
| `internal/win32` | 两边都要用的小工具，只写一份 | `win32.go` `single.go` |
| `internal/mcp` | MCP 协议层：`initialize` / `tools/*` / `resources/*`，只用标准库 | `mcp.go` |

## 边界与链路

依赖方向自上而下，`app → ui → store → i18n`；`rdp` 不 import `app`/`ui`。
`locales` 是叶子包（只 import mygo 的 i18n），`ui` / `app` / `rdp` 都能直接调它的 accessor。

进程间靠命令行衔接：GUI 按钮 `exec` 本 exe 的 `desktop`/`start`/`status`/`stop`，所以
`internal/app` 不 import `rdp`/根包；唯一向上一跳是 `internal/rdp/gui_shim.go` 调 `app.Run` 开窗口。

RDP 控件怎么嵌进去、登录后各阶段的时序，见 [使用说明.md 第 6 节](使用说明.md)。

## 改动前必读

- `IPersistStreamInit::InitNew()` 在 `SetClientSite` 之前调用会让 mstscax 崩溃 → 本实现默认跳过。
- 控件 QI `IOleInPlaceSiteEx`；不提供它控件走 windowless 模式，永远白屏；提供了才建真窗口。
- `DoVerb` 成功后必须 `SetObjectRects`，否则控件窗口高为 0。
- `WM_CLOSE` 里先 `Disconnect()` 再退出；直接在事件回调里 `DestroyWindow` 会卡死。
- 文案改 `locales/*.json`，然后 `go tool mygo generate` 重新生成 `locales/catalog_gen.go`：
  它是生成物，`mygo build` 也会顺手生成，手动改会被覆盖。新的 key 要同时进 en 与 zh-Hans，
  `go test ./locales` 会查漏 key、多 key、空值、参数不一致。
- `VARIANT` 在 x64 是 24 字节；`DISPPARAMS.CArgs` 是 `int32`；参数数组要**逆序**填。
- Go 回调进 COM 的线程必须 `runtime.LockOSThread()` 且跑自己的消息循环。
- `AdvancedSettings.SmartSizing` **只缩不放**：窗口小于桌面时整幅画面缩小铺满，大于桌面时 1:1 居中，
  控件没有任何 zoom 属性。试过在每次 `WM_SIZE` 后重设该标志、以及额外调 `IOleObject::SetExtent`，都不放大。
  要大画面只能调 `desktopScaleFactor`（`--scale`）。RDCMan 同样只用这个标志，它那个“真正变大填满”的
  模式是 `Reconnect with new resolution`（改分辨率）。
- 尺寸档：`applyDisplay` 里 fixed 与 scale 合并成 `w, h, ds = s.baseW, s.baseH, s.baseScale`，
  `WM_SIZE`/`WM_DPICHANGED` 对这两档不重设分辨率，所以**退出全屏必须由 `leaveFullscreen()` 主动调一次
  `applyDisplay(s)`**（漏了就会停在全屏的 1920×1080）。全屏时的档位停用/恢复在
  `suspendSizeModeForFullscreen()`，`RunRdpSession` 与 `enterFullscreen` 共用。
- 最小桌面只有一处定义：`kMinDesktopW/kMinDesktopH`（480×320），`hostState.viewSize()` 委托包级
  `viewSize(hwnd, opt)`，`WM_GETMINMAXINFO` 用同一对常量；`applyDisplay` 里不要再自己兜底。
- 初始窗口尺寸在 `defaultWindowRect(opt)` 里按工作区截断（超过就缩到工作区，返回的 `clamped` 用来提示），
  否则 1080p 屏选 2560×1440 时窗口居中到负坐标，顶栏跑出屏幕、拖不回来。
- `UpdateSessionDisplaySettings` 的物理尺寸按 `w*254/(10*dpi)` 算，外面那两个 `clampI32(...,10,10000)`
  实际够不着（1920×1080 @96dpi 才 508×286 mm，要 37800 像素宽才撞上限），排障时别在它们身上找原因。
- 改了 `internal/rdp/host*.go` 或 `internal/ui/*` 之后**必须重启 GUI 进程**：`click`/`open` 投递的是
  配置文件，由正在跑的旧进程消费，看起来就像“改了没生效”。
- 新增一个已知故障时要改两处：`internal/fault/fault.go` 里加常量与那一句话，
  `docs/故障代码.md` 里写判据与处理（`fault_test.go` 会核对每个代码都在文档里出现过）。
  程序里只显示代码与一句话，不要往界面上塞长解释。

## 阅读顺序

1. `main.go` → `internal/rdp/run.go`（命令怎么分）→ `host_run.go` + `host_wndproc.go`（窗口与消息循环）→ `ax.go` + `dispatch.go`（COM 容器）
2. `internal/rdp/rdp.go`（属性配置）→ `env.go` + `session_launch.go`（子会话与进程）
3. `internal/app`（窗口逻辑）→ `internal/ui`（绘制）→ `internal/store`（设置与密码）
4. 专项：`bar.go` / `overlay.go`（顶栏与浮条）、`mcp.go` + `mcp_tools.go`（AI 接口）

## 构建与资源

```pwsh
pwsh .\Scripts\build.ps1                 # mygo 打包 + -X 注入，产物 build\windows-amd64\localrdp.exe（带 -Version 才多一个 zip）
pwsh .\Scripts\build.ps1 -Clean -Test    # 先清 build、先跑 go vet 与 go test
go run ./tools/genicon           # 重画 winres\localrdp.png 与 localrdp-session.png
```

- 版本号是 SemVer（`主.次.修`），只认 `mygo.json` 的 `version`；`Scripts/build.ps1` 经 `MYGO_LDFLAGS` 把同一个数字写进
  `localrdp/internal/rdp.versionString`，打包完再从 exe 属性里读回来对比，对不上就报错。
- 图标与版本信息、manifest 都由 `go tool mygo build` 注入（`build.go:570` 往主包临时写一个
  `mygo_windows_amd64.syso`，编完就删）——所以仓库里没有 `.syso`，也不该有：包里出现别人的
  `.syso` 时 mygo 会让位给它。裸 `go build` 出来的 exe 没图标没版本。
- `winres/localrdp.png` 是图标的唯一来源（`tools/genicon/main.go` 画，`main_test.go` 守着
  “PNG 与画法一致”）；mygo 把它缩成 16/24/32/48/64/128/256 七档，`internal/rdp/misc.go`
  的 `loadAppIcon` 按图标组 ID 1 从 exe 里取回来。
- 一个 exe 只带一组图标，所以会话窗口那张（右下角带琥珀色点，`winres/localrdp-session.png`）
  不烤进资源，而是 `go:embed` 进二进制（`winres/embed.go`），运行时由 `internal/rdp/hicon.go`
  的 `sessionIcon` 缩成 16/32 做成 HICON。两张图都由 `go run ./tools/genicon` 一起重画。
- CI：`.github/workflows/ci.yml` 在 `windows-latest` 上跑 `go vet ./...` / `gofmt -l .` / `go test ./...` /
  `go tool mygo build`，push 与 PR 都触发。
