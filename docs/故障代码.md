# 故障代码

程序把**已经搞清楚的失败**编成 `E###`，只报代码和一句话，细节（怎么确认、怎么修）
全在这一页。看到代码就来这里搜它。

| 你会在哪里看到 | 长什么样 |
| --- | --- |
| 主窗口状态栏 / 通知 | `E202 连接在 TLS 握手阶段被本机中断，多为 TermService 的传输状态坏了，详见 docs/故障代码.md` |
| 会话窗口所在进程的 stderr（命令行模式） | 同上，失败时最后一行 |
| 日志 `%LOCALAPPDATA%\LocalRDP\localrdp.log` | `[ERROR] E202 …` |
| `localrdp status` 的 `Fault` 行 | 只有环境类 `E1xx` |
| MCP `lrdp_diag` 的 `fault_code` 字段 | `"E202"` |

代码的百位是阶段：`E1xx` 会话还没开（机器环境），`E2xx` 连接/登录阶段，`E3xx` 已经
进了子会话、在里头出事。**找不到代码就不是已知故障**，按 [使用说明.md](使用说明.md)
第 7 节的条目查。

| `E103` | 启动前 | 当前进程就在子会话里 |

| `E105` | 启动前 | 子会话传输建不起来 |

| `E204` | 登录时 | 账号或密码被拒 |

## E1xx 会话还没开：机器环境

这些在 `localrdp status` 里也能看到（`Fault` 行 + `NextAction`），此时开不了会话是
预期行为，程序不会硬连。

### E101 Windows 家庭版

家庭版没有 RDP 服务端组件，子会话无从谈起。判据：`localrdp status` 里
`EditionID=Core…`、`HomeEdition=yes`。换专业版/企业版/教育版/Server。

### E102 控件没注册

判据：`RdpControlRegistered=no`。`mstscax.dll` 不在或 COM 注册被精简掉。修：

```pwsh
regsvr32 /s %SystemRoot%\System32\mstscax.dll
```

还是 no 就是系统被精简过（第三方精简版常见），换原版系统。

### E103 在子会话里运行

子会话里不能再开子会话。判据：`InsideChildSession=yes`、`CurrentSessionId` 与
`ChildSessionId` 相同。回到父会话（控制台那个桌面）再启动。

### E104 子会话功能是关的

判据：`ChildSessionsEnabled=no`。`localrdp start` 会自己开（需要一次管理员确认）；
图形界面里打开子会话时同理。没弹出确认就说明当前不是管理员，按
[手动授予特权.md](手动授予特权.md) 的说明手动开。

### E105 子会话传输建不起来

判据：`Transport` 不是 `0x00000000`（`0x800706BA` = RPC 服务器不可用，`0x80070005`
= 拒绝访问）。常见原因：安全软件拦 `winsta.dll` 的
`WinStationCreateChildSessionTransport`、系统组件受损。重启一次系统后重试；仍旧
失败就查安全软件的拦截日志。

### E106 TermService 没在运行

判据：`TermServiceRunning=no`。本机 RDP 服务端不在，连 `localhost` 也没人应答。

```pwsh
gsudo pwsh -NoProfile -Command "Start-Service TermService"
```

## E2xx 连接与登录

### E201 控件不支持子会话

判据：日志里 `ConnectToChildSession 设置失败 0x80004005`，随后打印
`Failed to set ConnectToChildSession. Use the NotSafeForScripting RDP control.`。
说明用的是脚本安全的旧版控件。确认 `mstscax.dll` 是完整版（见 E102），别用第三方
精简的 ActiveX 包装。

### E202 TLS 握手被本机中断

最常见的一个，2026-11-10 本机复现过，与程序版本无关。

- 现象：会话窗口刚出现（或还没画出画面）就自己关掉，状态栏是 `E202 …（0xD07）`。
- 判据：日志 `事件 OnDisconnected` 之后是
  `OnDisconnected disconnect reason=0xD07 extended=0`；`localrdp status` 里环境全绿。
- 事件日志（`eventvwr.msc` → 应用程序和服务日志 → Microsoft → Windows →
  **TerminalServices-RDPClient/Operational**）里是这几条：

  ```
  1024 RDP ClientActiveX 正在尝试连接到服务器(localhost)
  1029 Base64(SHA256(UserName)) = …
   226 警告 RDPClient_SSL: 从 TsSslStateHandshakeInProgress 转换为
        TsSslStateDisconnecting 以响应 TsSslEventHandshakeContinueFailed
        时遇到错误(错误代码 0x80004005)
  1105 已断开多传输连接。
  1026 RDP ClientActiveX 已断开连接(原因= 3335)
  ```

  正常连接时应该有 `1028 服务器支持 SSL = supported` 和 `1025 已连接到服务器`，
  这两条缺失就说明握手中断了。服务端（`RemoteConnectionManager`）通常只有一条
  `261 侦听程序 … 已收到一个连接`，没有别的抱怨——因为根本没走到建会话。
- 处理：重启本机 RDP 服务端的传输（不需要动系统其他部分）：

  ```pwsh
  gsudo pwsh -NoProfile -Command "Restart-Service TermService -Force"
  ```

  然后重开子会话即可。
- 为什么重启服务就好了：握手状态由 `tssecsrv` 持有，它在某种情况下（例如开机后
  客户端第一次连接）会停在半开状态，重启服务清掉它。日志/事件里没有证书错误、
  也不是密码问题——本机证书 `CN=<计算机名>` 有效、`cred.dat` 解出的密码
  `LogonUser` 能过，都排除过。

### E203 超时，一直没连上

判据：日志里反复出现 `仍然等待中 Connected=0`，最后是 `E203 …（0x108）` 或
`E203 …（90 秒内没有连上）`。`--timeout` 改的是这个秒数。常见原因是凭据框挡住
（见 [使用说明.md](使用说明.md) Q1/Q3）、或者 `E202`/`E205` 那类断开没上报。

### E204 账号或密码被拒

判据：detail 是 `0x807`，日志 `OnDisconnected Logon failed: credentials rejected.`。
密码错/账号被锁/口令过期。清掉缓存重填：

```pwsh
.\localrdp.exe click forget-password
```

### E205 被另一个连接接管

判据：detail 里的 extended 理由是 5，日志
`OnDisconnected The child session was taken over by another connection (only one is allowed).`。
全机只允许一个子会话：`localrdp stop`，或者关掉另一个窗口再开。

### E206 连接被断开（其它原因）

detail 是控件给的十六进制原因码。对照：

| 原因码 | 含义 |
| --- | --- |
| `0x204` | 子会话传输不可用（配合 E105 看） |
| `0x406` | 安全数据无效 |
| `0x706` | 环回证书校验失败（证书被换掉/时钟不对） |
| `0x904` | 连接被关闭 |
| `0x1607` `0x1707` | 凭据委派被策略阻断，自动登录走不通（见 Q1） |

拿不准就把 `localrdp status`、日志尾部、以及这一行代码一起贴出来。

### E207 控件起不来 / 报致命错误

判据：`创建控件失败`（三个 CLSID 都建不出来），或 detail 是 `错误码 N`（控件自己
报的致命错误）。先按 E102 确认组件在；还有问题就是系统组件受损，`sfc /scannow`
之后重试。

## E3xx 已经在子会话里

### E301 要跑的程序没启动

会话连上了，但 `--` 后面那个程序没进去。判据：日志
`WTSQueryUserToken unavailable: 0x00000522 (客户端没有所需的特权。)`、
`CreateProcessAsUser failed`、`LaunchInSession failed: no launch method worked`。
`start` 模式需要两项账户特权，按 [手动授予特权.md](手动授予特权.md) 授予后**重新登录**。
只要桌面不要程序就用 `desktop` 模式（不带 `--`）。

### E302 剪贴板桥没起来

子会话里的 CF_HDROP 桥进程启动失败，**文件**复制粘贴不可用（文本剪贴板走 RDP
自带的 CLIPRDR，不受影响）。多半还是 E301 那个特权问题；日志里紧跟
`Clipboard bridge started in child session` 才是正常的。

## 增改代码（维护者）

新认出一个失败时，两处一起改，缺一处测试就红：

1. `internal/fault/fault.go`：加常量 + `about` 里的那一行（程序里只显示这行）；
2. 本文件：加进「一览」表，并写一节说明判据与处理。

`internal/fault/fault_test.go` 会核对每个代码都在本页出现过。别把代码塞进退出码
（退出码只有 0/1/2/4/5/6 几个语义，见 `internal/rdp/common.go` 的 `ExitCode`）。
