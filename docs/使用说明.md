# LocalRDP 使用说明（Go 版）

> 用 RDP 的 loopback 连接，给**当前用户**在本机开一个"子会话"（child session =
> 同一账号的第二次交互式登录），得到一个**带 Explorer 的完整第二桌面**。
> 显示器/键盘/鼠标隔离，文件、用户配置、已装软件共享。
>
> 本项目是 [charles-cty/LocalRDP](https://github.com/charles-cty/LocalRDP)（MIT）的
> **纯 Go 重写版**：不依赖 MSVC / CMake / ATL，`go build` 直接产出单文件 exe。
> 本文结论均在本机（Windows 10 专业版 build 19045、本地账户、单用户）实测。

---

## 1. 它是什么，不是什么

- **是**：一个窗口里塞着你的第二个完整桌面，和当前桌面用 Alt+Tab 来回切。
- **不是**：隔离/沙箱/安全边界。子会话里的程序能读写你的一切文件。
- **限制**：全机同时只能有 **1 个**子会话；家庭版没有 RDP 服务端，用不了。

典型用途：演示/录屏时藏起私人窗口、需要"干净桌面"、测试多桌面/DPI、双开同一个账号的图形程序。

## 2. 编译

```pwsh
cd C:\src\LocalRDP-go
pwsh .\Scripts\build.ps1                     # -Clean 先清空 build，-Test 先跑 go vet 与 go test
```

打包只用 `go tool mygo build`（`Scripts/build.ps1` 就是帮你跑它、注入版本）。直接跑裸
`go build .` 也能编译，但出来的 exe **没图标、没版本信息**，`localrdp status` 会打 `dev`：
图标、版本信息与 manifest 都是 mygo 打包时临时写进主包再删掉的，不经它就没有。

产物在 `build\windows-amd64\localrdp.exe`（旁边躺着要一起发出去的 `LICENSE`），**不依赖 VC 运行时**。
本地构建只出 exe；带 `-Version <版本>`（发版与 CI 用这条）时才会额外在 `build\` 里压成
`localrdp-<版本>-windows-amd64.zip`，约 4 MB，把 exe 与这个 zip 一起传上 Release，见下面「发版」。

exe 的名字、版本、图标、产物目录都在根目录的 `mygo.json` 里（`name` 决定 exe 文件名，
`windows.displayName` 决定属性里显示的名字）。换图标就跑

```pwsh
go run ./tools/genicon           # 重画 winres 下两张 PNG，别手改
```

图标本身是 `tools/genicon/main.go` 画出来的：蓝色圆角方块上白色文件夹加号，与窗口标题栏左上角
那个图标同形（`internal/ui/icons.go` 的 `iconApp`）。它画成 256 像素的 PNG，mygo 打包时缩成
16/24/32/48/64/128/256 七档写成 exe 的图标组；`tools/genicon/main_test.go` 会在 PNG 与画法
脱节（改了画法忘了重跑）时失败。另有一张 `localrdp-session.png`：同一张图右下角多一个琥珀色点，
给会话窗口用（见 §5.3），不烤进资源而是 `go:embed` 进二进制。

版本号是[语义化版本](https://semver.org/lang/zh-CN/)（SemVer 2.0.0）的 `主.次.修`，如 `1.4.2`：
不兼容的改动 +主、加功能 +次、修 bug +修；预发布缀在修订号后面（`1.4.2-rc.1`，Windows 的
版本资源只看数字部分）。tag 是 `v` 加版本号，取 tag 去掉 `v` 的那一串就 `mygo.json` 的 `version`
（`v1.4.2` → `1.4.2`）。发版三步：改 `mygo.json` 的 `version` → 提交推到 `main` → 打 tag 推上去。

```pwsh
git tag -a v1.4.2 -m "LocalRDP 1.4.2"
git push origin v1.4.2
```

`.github/workflows/ci.yml` 只有一个 workflow：普通 push 与 PR 跑 vet / gofmt / 测试 / 链接自检（不打包）；
推 `v*` tag 时多跑一个 `release` job，它用 `build.ps1 -Version <tag 去 v>` 出包（版本对不上
直接失败）、验 exe 能跑，直接把 exe 与 zip 传成 Release。本地 `pwsh .\Scripts\build.ps1` 仍可手工出包（只出 exe，
要 zip 就带 `-Version`），只是不再手工发版。这个数字被两处读走：mygo build
写进 exe 的版本信息，`Scripts/build.ps1` 经 `MYGO_LDFLAGS` 用 `-X` 写进
`localrdp/internal/rdp.versionString`（`localrdp status` 与 MCP 的 server version 都读它），
打完再从 exe 属性里读回来对账，对不上就报错。`-Version` 是断言模式的入口：给了它就不看
`mygo.json` 的版本改没改，只要求两边就是这一串（CI 发版就靠它）。

仓库里**没有 `.syso`**：图标、版本信息、manifest（PerMonitorV2 + comctl32 v6）都由
`go tool mygo build` 往主包里临时写一份再删（`build.go` 里的 `mygo_windows_amd64.syso`）。
所以别手工塞一个进去——包里出现别的 `.syso` 时 mygo 会让位给它，图标与版本就不会被注入了。
程序启动时会把图标挂到会话窗口上（`internal/rdp/misc.go` 的 `loadAppIcon` 从 exe 资源里按
大、小两个尺寸各取一张，写进窗口类再补一次 `WM_SETICON`）：任务栏按钮、任务栏缩略图和 Alt+Tab
都读窗口自己的图标，没设就只能画一个通用的空壳。

`-H=windowsgui`（mygo 打包时自动加）让 exe 编成图形子系统程序：**双击不会有黑框控制台**。
命令行用法靠程序自己 `AttachConsole` 挂回父终端（`internal/win32/win32.go` 的 `AttachStdio`），
所以 `.\localrdp.exe status` 在终端里照样看得见输出；输出被接到管道或
文件时（`| Out-File`、`$out = & localrdp.exe status`）直接用继承的句柄。

依赖：`github.com/lxn/win`（Win32 syscall 绑定）、`golang.org/x/sys`、`github.com/egoist/mygo`
（窗口与打包；mygo 以 `go tool` 的方式钉在 `go.mod` 里，存仓后 `go tool mygo` 直接可用）。

## 3. 首次使用需要什么（一次性）

| 项目 | 必需性 | 怎么做 |
| --- | --- | --- |
| Windows 子会话开关 | **必需** | 首次 `desktop`/`start` 会自动调 `WTSEnableChildSessions(TRUE)`，需管理员，会**自动二次提权**（UAC 确认一次）。不用重启，立即生效 |
| `SeTcbPrivilege` + `SeAssignPrimaryTokenPrivilege` | 只有 `start` 模式需要 | 手动授予，见 **[手动授予特权.md](手动授予特权.md)**（`secpol.msc` 图形步骤或一段可复制的 pwsh 片段）。程序里**没有**按钮，也不再附带脚本 |
| 重新登录 | 授予特权后需要 | 特权是登录时写进令牌的，**必须注销重登**（或重启）才生效 |

验证特权是否生效：

```pwsh
whoami /priv | Select-String 'SeTcb|SeAssignPrimaryToken'
# 期望两行都在；看不到 = 还没重登
```

> 不授予这两个特权也能用 `desktop`（完整桌面），只是 `start -- 程序` 会失败。
> 详细说明（含风险、撤销、验证）：[手动授予特权.md](手动授予特权.md)。

## 4. 快速开始

### 方式 A：图形界面（推荐）

双击 `localrdp.exe`（不带参数）就是窗口。整个窗口一页：页头是**新会话…**和右上角的**打开子会话**，
下面两列卡片。打开会话之后换成该会话的页；标题栏右边的 ＋ 回到表单。

左列三张卡，末尾跟一张日志：

| 卡片 | 内容 |
| --- | --- |
| 账号 | 用户名、密码（右侧的「清除」只清这一格）、缓存密码开关；卡头「清理密码」删掉记住的密码 |
| 会话设置 | 启动程序：连上后在子会话里跑什么，比如 `notepad.exe` 或 `pwsh.exe -NoExit`；留空就只开桌面 |
| 运行状态 | 子会话与密码缓存两格读数（圆点说明是/否）；卡头三个图标：打开数据目录、刷新、注销子会话（有会话时才出现） |
| 日志 | 默认收起，卡头箭头展开；另有复制、清空 |

右列一张卡「**宿主窗口与显示连接设置**」：标题；**窗口大小**三档（固定大小 / 跟随窗口 / 拉伸，见 5.2）；
**分辨率**十个胶囊（1024×768 … 2560×1440）点一下就填进宽/高并锁定该尺寸（宽/高变灰、只读），
要自己填就点「自定义分辨率」解锁，右侧徽标说明现在是「已锁定预设」还是「自定义编辑中」；
分隔线下是窗口状态与连接选项（全屏、保留会话、最小化、禁用缩放自动继承）和超时(秒)。

「打开子会话」按钮对应当前表单 + 记住的上次参数（`%LOCALAPPDATA%\LocalRDP\settings.json`）；
窗口尺寸填 0 就用默认的 5/6 工作区。

标题栏只有图标和名字，右上角的齿轮是设置：一张卡里放着语言分段和两个开关（记住密码、记住上次的会话）。没有菜单栏，也没有左侧会话栏：
打开子会话后，一张「会话卡」浮在表单上：程序、用户名、状态、宿主窗口、退出码，底下是
刷新 / 重连 / 关闭会话 / 显示窗口四个按钮。按 Esc 或点卡片外面把它收起，表单原样还在；
标题栏右上角的显示器图标，或者顶栏那个「回到会话」，都能再把它叫出来。
设置里改了语言会立刻预览，点保存才写进 `settings.json`；取消、按 Esc 或点卡片外面会把语言退回去。
窗口窄于 980 像素时两列并成一列，顺序是 账号 → 会话设置 → 运行状态 → 宿主窗口，日志仍在最后。
动作做完时窗口右下角弹一条提示（已打开、已注销、已清理密码等），不用翻日志找结果。

一个登录会话只开一个窗口：重复双击不会再开第二个，只会把已在运行的那个叫到前面。

### 方式 B：命令行（直接用 exe）

```pwsh
.\build\windows-amd64\localrdp.exe desktop                  # 子桌面，窗口一直开着
.\build\windows-amd64\localrdp.exe desktop --fullscreen      # 全屏启动（Ctrl+Alt+F 切换）
.\build\windows-amd64\localrdp.exe start -- notepad.exe      # 子会话里只跑 notepad，退出后会话注销
.\build\windows-amd64\localrdp.exe start --keep-session -- pwsh.exe
.\build\windows-amd64\localrdp.exe status
.\build\windows-amd64\localrdp.exe stop
.\build\windows-amd64\localrdp.exe click fullscreen          # 按会话窗口顶栏的按钮，不用鼠标
.\build\windows-amd64\localrdp.exe click open                # 按主窗口「打开子会话」
.\build\windows-amd64\localrdp.exe click forget-password     # 清除缓存密码
```

### 方式 C：密码走环境变量

```pwsh
$env:LRDP_PW = '你的密码'      # 也可用 setx 预置
build\windows-amd64\localrdp.exe desktop --user "$env:USERDOMAIN\$env:USERNAME" --password-env LRDP_PW --title '子桌面'
```

### 完整参数

```
localrdp <命令> [选项] [-- <程序> [参数...]]

命令:
  status                  显示环境/依赖/子会话状态
  start  [选项] -- <程序>  在子会话里运行一个程序（需 SeTcb 特权）
  desktop [选项] [-- 程序] 打开完整子桌面（可选同时启动程序）
  stop                    注销子会话
  help | --version

选项:
  --width N --height N --x N --y N   窗口尺寸/位置（默认工作区 5/6，居中；比工作区大就按工作区截断）
  --size fit|fixed|scale             窗口大小与桌面的关系（见 5.2；scale 界面叫「拉伸」）
  --fixed                            等价于 --size fixed
  --scale N                          桌面缩放百分比 100-500（默认不设 = 100；界面默认留空）
  --no-scale-inherit                 缩放留空时不把屏幕的缩放（150% 等）传给子会话，固定 100%（见 5.2）
  --fullscreen                       全屏启动
  --title TEXT                       标题/连接栏文字
  --workdir PATH                     程序的工作目录
  --user 域\用户  --password-env VAR --password PW
  --minimized --hidden               最小化 / 隐藏启动
  --no-clipboard                     不重定向剪贴板
  --drives                           重定向本地驱动器（默认关）
  --view-only                        只读显示
  --keep-session                     程序退出后不注销子会话
  --timeout SEC                      连接超时，默认 90（最小 5）
```

## 5. 两种模式怎么选

### 5.1 desktop 还是 start

| | `desktop` | `start -- 程序` |
| --- | --- | --- |
| 表现 | 完整第二桌面，Explorer 常驻 | 子会话里只跑指定程序 |
| 程序退出后 | 会话仍在，手动关窗口 | 自动注销子会话，CLI 返回 |
| 需要 SeTcb 特权 | **不需要** | **需要** |
| 文件剪贴板 | ❌（桥起不来，见 Q6） | 授权+重登后 ✅ |
| 文本剪贴板 | ✅ | ✅ |
| 何时用 | 长期挂一个干净桌面 | 快速跑一个临时程序 |

**没有特权时就用 `desktop`。**

界面里的「启动程序」就是 `desktop -- 程序`：桌面照开，程序在桌面上启动，退出后会话还在。
图形界面不再产生 `start`（它留给脚本）；会话的 `desktop`/`start` 只影响“程序退出后跑不跑”，
而窗口要的是一个不会自己关的桌面。

### 5.2 窗口大小：固定 / 跟随 / 拉伸

界面「窗口大小」或命令行 `--size` 三个档，对应 `settings.json` 里的 `size_mode`：

| 档 | 关键参数 | 窗口能拖动吗 | 拖动后桌面 | 字会变小吗 |
| --- | --- | --- | --- | --- |
| 固定大小 | `--size fixed` | ❌ 拖不动、最大化也无效 | 保持 `--width`×`--height`（屏幕放不下时按工作区截断） | 不会 |
| 跟随窗口 | `--size fit`（默认） | ✅ | 重新协商成窗口大小 | 窗口变大会变小 |
| 拉伸 | `--size scale`（界面「拉伸」） | ✅ | 分辨率不变；窗口比桌面小时整幅画面缩小铺满，比桌面大时保持原尺寸居中（留灰边，不放大） | 不会 |

只有拉伸档把 `--scale` 交给会话（默认不设 = 100，跟随与固定一律 100），**不跟随屏幕 DPI**：
画面尺寸由分辨率决定，与屏幕 DPI 无关。以前把屏幕 DPI 也塞进缩放因子，等于同一块内容先按 150%
排版、再被画面拉伸一次（= 放大两次）；要让子会话里的字变大，就显式写 `--scale 150`。

**分辨率按 DPI 折算**：界面/命令行里的宽高是**逻辑像素**，真正要来的桌面是 `宽×dpi/96`。
150% 屏上选 1024×768，会话是 1536×1152，窗口也开成 1536×(1152+顶栏)，与主窗口同一视觉尺寸
（`internal/rdp/winutil.go` 的 `dpiPx`，dpi 取窗口所在显示器，见 `startDPI`）。不折算的话
1024×768 物理像素在 150% 屏上只有 683×512 逻辑，整块缩成 2/3，拖动区域与顶栏按钮都跟着小。
日志判据：150% 屏上 `--size fixed --width 1024 --height 768` 打的是
`会话尺寸基准 1536x1152（size=fixed）`（未折算时是 `1024x768`）。

实现要点：`internal/rdp/host_wndproc.go` 与 `host_display.go` 里 `sizeMode` 控制三件事：`WM_GETMINMAXINFO` 把最小/最大
都钉成 `fixedW/fixedH`（并去掉 `WS_THICKFRAME`），fixed 与 scale 都不换分辨率，会话一直是连接时
那个桌面（`baseW×baseH` @ `baseScale`），fixed 下窗口也钉成这个尺寸，scale 下窗口可以拖动、
由控件的 `SmartSizing` 把画面适配进窗口。
**`SmartSizing` 只缩不放**：窗口比桌面小时整幅画面按比例缩小铺满（不变形），窗口比桌面大时
画面保持 1:1 居中、四周留灰边——控件不会把画面放大，`AdvancedSettings` 里也没有任何 zoom 属性
（RDCMan 的「Scale to fit window」用的就是这个标志，它能让画面真正变大填满的是另一个模式
`Reconnect with new resolution`，代价是改分辨率）。所以想让字真的变大，只能在连接时调
`--scale`（界面「缩放 %」）决定桌面的像素数，而不是靠拉窗口。
`WM_SIZE` 在 scale 档不重设显示设置，`WM_DPICHANGED` 也不重设（分辨率跟窗口无关）；
只有 fit 档在拖动后把分辨率重新协商成窗口大小。
`SmartSizing` 在 fit 与 scale 两档开，fixed 关。
全屏期间尺寸档失效（按跟随屏幕处理），退出全屏后恢复（`Ctrl+Alt+F` 进出也守这个规则）。
日志判据：`会话尺寸基准 1280x800（size=scale）`，之后拖动窗口**不应**再出现 `Display updated`。
像素判据：会话 1592×822 放进 1704×1044 的窗口，截图里桌面区域正好 1592 像素宽、上下各留 ~89px 灰边。

界面上「分辨率」那一排是胶囊按钮（1024×768 … 2560×1440），点一下就把宽高填进表单并锁定该尺寸
（宽/高变灰只读）；要自己填就点「自定义分辨率」解锁。再选「固定大小」，开出来的窗口就是这个分辨率且拖不动。

要的尺寸比工作区还大（1080p 屏上点 2560×1440 就是这样）时，窗口按工作区截断并居中，
stdout 与日志各留一句 `The window does not fit the screen; using WxH.` / `屏幕放不下，窗口改成 WxH`：
比屏幕还大的窗口有一半落在屏幕外，顶栏（拖动、关闭都靠它）跟着看不见。固定档的桌面同样跟着小下来
（桌面 = 客户区减顶栏），不会画到屏幕外面去。

「缩放 %」框**默认是空的**，空 = 不请求缩放（等价 100），不是 0 号缩放；填了就必须是 100–500，
否则表单报 `缩放要填 100–500 之间的百分比，或者留空。`。它最终作为 `--scale` 传给会话，
只有「拉伸」档会读（跟随与固定即使填了也是 100，否则同一像素会被缩两次）。

**缩放留空时，子会话仍然跟着屏幕缩放走**：`UpdateSessionDisplaySettings` 除了宽高还报一个物理尺寸，
子会话桌面的 dpi 由它算出来，而那个 dpi 取的是窗口所在屏的 dpi——150% 的屏上子会话就是一个 150% 的
会话，字和控件跟主机窗口一样大（见 `internal/rdp/rdp.go` 的 `guestDPI`）。要一个固定 100% 的子会话，
勾「禁用缩放自动继承」（`--no-scale-inherit`，`settings.json` 里是 `no_scale_inherit`）：它只在「缩放 %」
留空时生效，把报给子会话的 dpi 钉成 96。上一条「宽高按 dpi/96 折算」不受它影响——窗口仍按逻辑像素开
（1024×768 在 150% 屏上还是 1536×1152 的像素），变的只是子会话按 100% 还是按屏幕缩放排版。
`start` 与 `desktop` 接受同一套尺寸选项，`--size` / `--scale` 在 `start` 上一样生效。
`start` 的 job 文件（`internal/rdp/job.go`，`LOCALRDP-JOB-1`）只把要运行的程序、工作目录、
`keep_session` 与 `desktop` 传给子会话里的 `--session-entry`，窗口尺寸与缩放不经过它。
最小桌面是 480×320（`kMinDesktopW/kMinDesktopH`，与 `WM_GETMINMAXINFO` 同源）：窗口比它更小时
会话按 480×320 兜底，再小的窗口只会把这块 480×320 缩小显示。

### 5.3 会话窗口的顶栏

这个窗口没有系统标题栏：整块客户区都是自己的，顶部那条栏（`internal/rdp/bar.go`，96 dpi 下高 40
像素，实际高度是 `40×dpi/96`：120% 50、150% 60、200% 80）就是标题栏。
深色底，左边说状态、右边是三个动作，最右是三个窗口按钮。栏里的字号、按钮高宽、图标尺寸同样按
`dpi/96` 折算（`newBarMetrics`），换到另一块不同缩放的屏幕上由 `WM_DPICHANGED` 里的 `setDPI` 重算。

| 元素 | 作用 |
| --- | --- |
| 左边标记与名字 | 蓝底图标 + `LocalRDP`，后面一条竖细线分隔 |
| 状态胶囊 | 圆点带颜色：绿点 `已连接` / 灰点 `已断开` / 黄点 `正在连接…` |
| 子会话胶囊 | 登录成功且拿到子会话号时才出现，`子会话 N`（人形图标） |
| 全屏 | 藏起这条栏，按 Esc 或 `Ctrl+Alt+F` 退出 |
| 重连 | `Disconnect()` 后 1.2 秒重新 `Connect()`，会话窗口不关 |
| 断开 | 断开 RDP 连接并关掉窗口（等同于点 ×），红底红字，是三者里唯一的危险色 |
| − □ ✕ | 最小化 / 最大化（已最大化时画的是还原）/ 关闭；悬停变灰，✕ 悬停变红 |

全屏时这条栏藏起来，画面铺满屏幕；把鼠标撞到屏幕上边缘，顶端中间会浮出一条小条
（`internal/rdp/overlay.go`），只有「全屏 / 重连 / 断开」三个按钮，鼠标移开它就收回去。
它浮在画面之上但不抢键盘焦点，点「全屏」直接退回窗口模式；它跟着全屏窗口一起出现和消失，
切到别的程序时不会浮在别人头上（每 120 毫秒的 `kTimerOverlay` 看一次指针位置）。

这条栏同时也是窗口的拖动条：按住空白处拖窗口、双击最大化或还原；拖窗口四边或四角改大小
（「固定大小」模式和全屏时不响应边缘，那时窗口尺寸由分辨率或屏幕决定）。按钮图标用系统自带的
`Segoe MDL2 Assets` 字形（全屏 `0xE740`、重连 `0xE72C`、断开 `0xE7E8`、人形 `0xE77B`、最小化
`0xE921`、最大化 `0xE922`、还原 `0xE923`、关闭 `0xE8BB`），不额外带图片资源。

这个窗口在任务栏上是**单独的一个按钮**，不和主窗口并在一起：它所在的进程在开窗口之前用
`SetCurrentProcessExplicitAppUserModelID` 给自己报了 `com.localrdp.desktop.session` 这个分组
（`internal/rdp/host_run.go` 的 `sessionAppID`），两个窗口于是各有一份缩略图、右键菜单与关闭动作。
不报的话 Windows 按 exe 路径分组，同一个 exe 的窗口会挤进一个按钮里（这就是主窗口与子会话
窗口“粘在一起”的原因）。

光分组还不够：两个按钮若同名同图，还是看不出哪个是会话窗口。所以会话窗口登录后在标题后面
挂上会话号（`LocalRDP · 子会话 48`，`internal/rdp/misc.go` 的 `sessionTitle`，由 `OnLogin` 调
`SetWindowText` 换掉），图标也换成右下角带一个琥珀色点的那张 —— 一个 exe 只能带一组图标，
这张因此 `go:embed` 在二进制里（`winres/localrdp-session.png`），运行时缩成系统要的边长做成
HICON（`internal/rdp/hicon.go`）；主窗口仍是 exe 自带的那张。

无边框是这么来的：`WM_NCCALCSIZE` 直接 `return 0`，客户区就等于整个窗口。建窗口时系统只会发
一次 `wParam == 0` 的那版，客户区仍按有标题栏算，所以建完还要补一次
`SetWindowPos(..., SWP_FRAMECHANGED)` 才真正去掉标题栏。最大化时 Windows 给的窗口矩形比屏幕大
8 像素（边框留在屏幕外），所以 `WM_NCCALCSIZE` 里对最大化状态把客户区四边各内缩
`SM_CXSIZEFRAME + SM_CXPADDEDBORDER`，让它正好等于工作区。

`WM_NCHITTEST` 把命中翻译回非客户区代码：窗口四周 `kGrip`（96 dpi 下 4 像素，随 DPI 折算）的环是
`HTLEFT`/`HTRIGHT`/…（不可缩放的模式下关掉），栏面是 `HTCAPTION`（拖动和双击最大化交给 Windows），
三个窗口按钮分别是
`HTMINBUTTON`/`HTMAXBUTTON`/`HTCLOSE`——悬停变灰、按下高亮由系统画，但**按下去要自己处理**：
没有真的标题栏时 `DefWindowProc` 不管这几个键，`wndProc` 在 `WM_NCLBUTTONDOWN` 里自己调
`ShowWindow(SW_MINIMIZE/SW_MAXIMIZE/SW_RESTORE)` 或走关闭流程。

整条栏不进 `--capture` 截图，想单独看外观可以 `go run -tags barpreview ./tools/barpreview -dpi 144`，
会把四种状态画成 `tmp_shot/bar_en.png` 与 `bar_zh.png`（`internal/rdp/barpreview.go`，构建标签之外的
代码不受影响）；`-dpi` 不写是 96，要核对 150% 屏的排版就写 144。

实现细节：控件住在本进程建的 `STATIC` 子窗口里（`hostState.view`），栏画在它上面；控件的
`IOleInPlaceSite::SetObjectRects` 只认尺寸不认偏移，所以不能直接把控件往下挪。顶栏按钮用
`PostMessage(hwnd, 0x8002, cmd, 0)`（`internal/win32` 的 `PostCommand` 与 `HostCommandMessage`）——
GUI 里点「重连」也是走这条路，`win32.BringToFront` 同样用类名 `LocalRDP.Host` 找窗口。

## 6. 原理（够用来排障）

```
localrdp desktop / start
  ├─ WTSEnableChildSessions(TRUE)           一次性，需管理员（首次自动提权）
  ├─ 建无边框宿主窗口（类名 LocalRDP.Host，黑色背景）
  │    顶部自绘栏 bar.go 兼作标题栏（重连 / 断开 / 全屏 / 最小化 / 最大化 / 关闭）
  │    控件住在 STATIC 子窗口里，占栏下面那块
  ├─ 纯 Go 嵌宿 RDP ActiveX 控件
  │    CoGetClassObject(CLSID {A0C63C30-F08D-4AB4-907C-34905D770C7D})
  │    SetClientSite -> OleSetContainedObject -> DoVerb(就地激活)
  │    QI IOleInPlaceSiteEx / IOleControlSite（缺了会白屏）
  │    SetObjectRects（不给尺寸也是白屏）
  │    IConnectionPointContainer -> Advise(IMsTscAxEvents)
  ├─ 配置属性：Server=localhost, AuthenticationLevel=0, EnableCredSspSupport=true
  │    ConnectToChildSession = true         ← 关键的非公开属性
  │    RedirectClipboard=true, RedirectDrives=false, DisableRdpdr=false
  │    DeviceScaleFactor/DesktopScaleFactor（本机无效）
  ├─ Connect() → 凭据登录 → 得到子会话（session 2/3/…）
  ├─ OnLogin 后：
  │    · 800ms 起剪贴板桥（需要把进程塞进子会话 → 需要特权）
  │    · 1500ms 起 session-entry（`localrdp --session-entry --job <file>`）
  │    · 显示同步 UpdateSessionDisplaySettings（必须在登录后）
  └─ 关窗口：Disconnect → Unadvise → Release → 注销子会话（--keep-session 可留）
```

把进程塞进子会话有三条路，代码里依次回退（`session_launch.go`）：

1. `WTSQueryUserToken` + `CreateProcessAsUser` —— 需要 `SeTcbPrivilege`
2. 在子会话里挑一个进程（explorer 优先）复制其令牌 —— 需要 `SeTcbPrivilege`
3. `CreateProcessWithTokenW` / 父进程属性 —— **没有特权时会静默建在当前会话**

每步都用 `ProcessIdToSessionId` 校验；进了错会话的进程立即 `TerminateProcess`，然后重试（最多 8 次）。

## 7. 常见问题

程序里出现 `E###`（状态栏、命令行 stderr、日志、`localrdp status` 的 `Fault` 行）就是
**已经搞清楚的失败**，代码含义与处理见 [故障代码.md](故障代码.md)；没有代码的按下面
Q1–Q9 查。

### Q1 会弹「你的凭据不工作 / 之前用于连接到 localhost 的凭据无法工作」

正常现象：本地账户没有 SSO 凭据可顺延，空凭据被拒。用菜单输一次密码即可（会缓存）。

### Q2 窗口"突然自己关了"

- `start` 模式且跨会话启动失败（特权不足），日志特征：
  ```
  WTSQueryUserToken unavailable: 0x00000522 (客户端没有所需的特权。)
  CreateProcessAsUser failed: 0x00000522 (客户端没有所需的特权。)
  New process pid=… is in session 1, expected 2; terminating it
  LaunchInSession failed: no launch method worked
  ```
  → 改用 `desktop`，或按 [手动授予特权.md](手动授予特权.md) 授予两项特权后**重新登录**。
- 你按了 Ctrl+C 或关了窗口 → 默认注销子会话。

### Q3 等了 90 秒报超时

多半是 Q1 的凭据框挡住，`OnConnected` 永不触发，watchdog 只能等超时。
先回滚日志（菜单第 6 项「查看日志」）找凭据/登录失败痕迹。
现在这类超时会带 `E203` 报出来（见 [故障代码.md](故障代码.md#e203-超时一直没连上)）。

### Q4 `A child session already exists (id=N)`

先 `localrdp stop`。若那个 id 其实早就注销了（`qwinsta` / `localrdp status` 里看不到），
新版会直接忽略它继续启动，日志里是 `忽略残留的子会话 id=N（WTS 枚举里已不存在）` ——
`WTSGetChildSessionId` 在会话结束后还会留着旧 id，不能只信它。

全机只允许 1 个子会话。先 `localrdp stop`。

### Q5 `--scale` 没反应

`--scale` 是在连接时把 `UpdateSessionDisplaySettings` 的 `desktopScaleFactor` 设成指定
百分比（`100-N%` → 窗口按 `N%` 渲染，所以 150 就是“UI 放大 1.5 倍”）。本机 20:29 实测
`--scale 150` 有效（截图里图标/文字明显变大）。旧版记的 `0x80004005` 是另一处调用路径失败，
现已改走 `internal/rdp/rdp.go` 的 `resolveScale` + `deviceScaleFor`。
不写 `--scale` 时**不再跟随屏幕 DPI**（那会在高 DPI 屏上把内容缩两次），一律 100。
屏幕的 dpi 只经由物理尺寸进到子会话的排版里，要它别进来就勾「禁用缩放自动继承」（见 5.2）。
想让“窗口变大而字不变大（只是看得更多）”请用 `--size fit`；想让“整块画面跟着窗口缩放”用 `--size scale`（界面叫“拉伸”，见 5.2）。
拉伸档不换分辨率：`--scale` 决定桌面按多大像素排版，窗口只把这块画面缩到放得下——**只缩不放**，
窗口比桌面大时画面 1:1 居中、四周留灰边。要更大的字只能加 `--scale`。
留空 = 不设 = 100，界面里这个框默认就是空的（表单校验要求 0 或 100–500，文案
`缩放要填 100–500 之间的百分比，或者留空。`）。

### Q6 复制的文件粘不进子会话

文件剪贴板靠自研 CF_HDROP 桥（`clip_bridge.go`），桥进程需要用特权塞进子会话 →
没有特权就起不来。日志里是 `E302 …`（见 [故障代码.md](故障代码.md#e302-剪贴板桥没起来)）。
**文本剪贴板不受影响**（走 RDP 自带 CLIPRDR 重定向）。

### Q7 白屏 / 只有黑窗口

窗口刚出来就自己关掉、状态栏是 `E202` 的，不是这里的问题——那是 RDP 传输层的 TLS
握手被本机中断，按 [故障代码.md](故障代码.md#e202-tls-握手被本机中断) 重启 TermService 即可。

先确认宿主窗口真的显示出来了：日志有 `Logon complete` 却看不到画面，多半是窗口建
好了但没被显示——子进程以 `SW_HIDE` 启动（`STARTF_USESHOWWINDOW`）时，Windows 会
忽略第一次 `ShowWindow`。`host_run.go` 在 `ShowWindow` 之后会再查一次 `IsWindowVisible`，
看不见就再显示一次；删掉这段症状会回来。

控件拿到了但没给尺寸也会白屏。现在的代码在 `DoVerb` 后立刻 `SetObjectRects`；
如果你改动了 `ax.go` 的 `create()`，注意别把这步漏掉。

### Q8 连上之后停在登录页 / 画面不动

子会话要靠 RDP 控件把**密码**交给服务端才能自动登录。密码没送到时，会话停在登录
界面，几十秒后被系统注销（事件日志里是「会话 N 已断开连接，原因代码 12」）。

`desktop` / `start` 不指定账户时，现在默认用当前账户 `DOMAIN\user`，密码取 DPAPI
缓存。判断有没有走上自动登录，看日志这两行：

- `ClearTextPassword（长度 N）hr=0x00000000 (操作成功完成。)` —— 密码已经交给控件；
- `OnLogin` 紧跟 `Logon complete. Child session id=N` —— 登录完成，桌面已就绪。

看到 `没有密码：子会话会停在登录页` 或 `密码没能交给 RDP 控件` 时，在界面里填好并
保存密码（或 `--password-env`）再试。

### Q9 想看日志

```pwsh
Get-Content "$env:LOCALAPPDATA\LocalRDP\localrdp.log" -Tail 50
```

### Q10 主窗口点「Show session」没反应

旧做法用 `AppActivate` 匹配窗口标题，标题和列表里的名字对不上时什么也不做。现在按
子进程 PID 找宿主窗口（`internal/win32/win32.go` 的 `BringToFront`），`SW_RESTORE`
之后提到前台，跟标题无关。

### Q11 双击后仍有一个黑框控制台

exe 是用 `-ldflags '-H=windowsgui'` 编的（`Scripts/build.ps1` 与 CI 都是），图形子系统程序本身
不会拿到控制台，所以正常情况下双击/`Start-Process` 都不会有黑框。还有黑框就查两件事：

- 用的是不是自己 `go build` 了没带 `-H=windowsgui` 的产物（控制台子系统构建会带窗口，
  `run.go` 里对无参数启动调用 `win32.FreeConsole()` 丢掉它，命令行模式则反过来
  调 `AttachStdio()` 接回父终端）；
- 黑框里如果是一个 tab（标题是工作目录），那是子会话里的**剪贴板桥**或用户程序，
  不是主程序的窗口；桥子进程用 `CREATE_NO_WINDOW` 启动（`launchFlags(hidden=true)`）。

### Q12 注销子会话后窗口不退，剩一块白屏

RDP 控件收到 `OnDisconnected` 后画面就黑了，窗口本身不会自己关。`host_events.go` 在事件里发
`wmRdpDisconnected`，`WM_CLOSE` 里看到「已断开」就直接 `PostQuitMessage`，日志可以对照：

```
OnDisconnected The child session was logged off.
WM_CLOSE ever=true done=false seen=true
会话已断开，退出窗口
消息循环已退出，开始清理
```

卡住的话看 `WM_CLOSE` 后面有没有「会话已断开，退出窗口」：没有就是事件没送到窗口；
有它还不退，就是清理阶段卡在 `release()`。另外注：断开之后**窗口定时器（`SetTimer`）
不一定还会触发**，所以“延时退出”不能只靠 `kTimerQuit`，现在同时有一个 2.5 秒的
goroutine 兜底（往窗口发 `wmRdpDisconnected`）。

### Q13 双击多次，开了好几个 localrdp.exe

现在一个登录会话只允许一个窗口：第二次启动会先试名叫 `Local\LocalRDP.Gui` 的互斥体，
拿不到就把已有的窗口（类名 `MyGoWindow`、标题 `LocalRDP`）显示到前面然后自己退出，日志写
「窗口已在运行，已把它叫到前面」。但 `desktop` / `start` 的宿主进程仍然是**一个会话一个**，
所以任务管理器里看到多个 `localrdp.exe` 是正常的：一个是窗口，其余是各个子会话的宿主。
用 `localrdp stop` 收掉当前会话；实在乱了就直接结束进程，会话本身会跟着注销。

### Q14 非正常关闭 / 同时开好几个，会出什么事

| 情形 | 结果 | 怎么收拾 |
| --- | --- | --- |
| 点 × 或「断开」 | `Disconnect()` → 注销子会话 → 窗口退出（`--keep-session` 则不注销） | 不用管 |
| 任务管理器强杀宿主进程 | 子会话**留在后台**（没注销），下次启动会看到残留 id 并被自动忽略（日志「忽略残留的子会话 id=N」） | `localrdp stop` 或界面「注销子会话」 |
| 断电 / 蓝屏 | 同上，重启后子会话通常已随系统清理，`localrdp status` 里 `ChildSessionId = 0` 就干净了 | `localrdp status` 看一眼 |
| 再双击第二个 exe | 互斥体拦住，把已有窗口叫到前面，自己退出（退出码 0） | 不用管 |
| 命令行再开一个 `desktop` | 已有子会话时报 `A child session already exists (id=N)`，退出码 5 | 先 `localrdp stop` |
| 子会话里注销了 / 被系统踢掉 | 宿主收到 `OnDisconnected`，窗口自动退出（`internal/rdp/host_events.go` 的 `wmRdpDisconnected` 通路） | 不用管 |

不会出现「泄漏的 RDP 连接」：连到本机子会话的 RDP 隧道随宿主进程结束就断，剩下的只是子会话本身
（一个没有登录用的容器），`logoff` 一下就回收。

## 8. 键盘 / 鼠标输入

**输入隔离是"会话级"的，跟焦点走**：点一下宿主窗口，键鼠立刻回到宿主；子会话不会抢。

- 唯一的按键相关配置是 `KeyboardHookMode=1`（"在远程计算机上应用 Windows 键组合"）：
  RDP 窗口有焦点时，Alt+Tab、Win 键等组合键发给子会话。
- 全项目**没有** `BlockInput`、**没有**低级键盘钩子、**没有**焦点劫持/置顶。
- **近似独占**：打开子桌面后按 `Ctrl+Alt+F` 全屏（`ContainerHandledFullScreen=1` + `HotKeyFullScreen='F'`），
  此时 Windows 键组合也进子会话。再按 `Ctrl+Alt+F` 退回。
- `Ctrl+Alt+Del`、`Win+L` 属于 SAS/系统快捷键，**不会**转发进子会话，作用于宿主。
- 启动 localrdp 的那个控制台窗口里按 `Ctrl+C` = 断开并注销子会话。

## 12. AI 排查接口（MCP）

`localrdp mcp` 在 stdin/stdout 上跑一个 Model Context Protocol 服务器（JSON-RPC 2.0，
protocol `2025-06-18`，无第三方依赖）。AI 客户端把它当子进程启动，就能自己看状态、翻日志、
列会话、启停会话、按按钮，不必再由人复制粘贴日志。

```pwsh
.\build\windows-amd64\localrdp.exe mcp          # stdin/stdout，供客户端调用
.\build\windows-amd64\localrdp.exe mcp --help   # 工具与资源清单
```

工具与参数、返回字段、协议细节、客户端配置、排障与「怎么加一个工具」，全部在
**[MCP.md](MCP.md)**。最省事的入口是 `lrdp_diag`：环境状态 + 会话列表 + 进程 + 最近 WARN/ERROR
日志一次拿全。

### 12.1 不开鼠标也能按按钮（`localrdp click`）

界面上的每个按钮都有一条命令行入口，AI 和脚本不用算坐标、不用模拟鼠标：

```pwsh
localrdp click --list                 # 列出全部按钮名
localrdp click fullscreen             # 会话窗口顶栏：全屏/退出全屏
localrdp click reconnect              # 会话窗口顶栏：重连
localrdp click disconnect             # 会话窗口顶栏：断开
localrdp click open                   # 主窗口：打开子会话
localrdp click status                 # 主窗口：状态
localrdp click stop                   # 主窗口：注销子会话
localrdp click show                   # 主窗口：显示窗口（把会话窗口拿到前面）
localrdp click close-session          # 主窗口：关闭会话
localrdp click forget-password        # 主窗口：清理缓存密码
localrdp click data-folder            # 主窗口：打开数据目录
localrdp click refresh / clear-log / copy-log
```

两条通路：

- **会话窗口**（`fullscreen` / `reconnect` / `disconnect`）：给宿主进程 `PostMessage(WM_APP+2)`，
  和点顶栏按钮走的是同一个 `command()`。默认找当前开着的那个会话窗口，可用 `--pid N` 指定。
- **主窗口**（其余名字）：往 `%LOCALAPPDATA%\LocalRDP\command.txt` 追一行，窗口每 120 ms 读一次并
  按同名按钮执行（和 `OnClick` 同一份代码）。窗口没开时命令直接报错，不会默默排队。

`localrdp click --pid 1234 fullscreen` 可以同时开好几个会话窗口时指定目标。按钮名写错会提示
`Unknown button: xxx. Try localrdp click --list.`。

按钮之外的东西不在 `click` 覆盖范围内：「窗口大小」三档是分段控件、宽/高/缩放是输入框，
要换档位只能改 `%LOCALAPPDATA%\LocalRDP\settings.json` 的 `last.size_mode`
（`fixed`/`fit`/`scale`）后重启界面。

## 13. 安全说明

- 密码缓存用 **DPAPI / CurrentUser**，只有同一 Windows 用户能解密；仍是可逆存储，
  共享机器上请用菜单 5 清除，或用 `-NoCache`。
- `--password`（命令行明文）不要用；封装脚本只用 `--password-env`。
- `SeTcbPrivilege` 是强特权（理论可绕过部分安全检查），仅授给本机单用户；
  不需要 `start` 模式时按 [手动授予特权.md](手动授予特权.md) 第 6 节撤销。
- 子会话**不提供**任何隔离。
