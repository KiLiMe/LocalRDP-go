# 手动授予特权（SeTcbPrivilege / SeAssignPrimaryTokenPrivilege）

> 本文替代原来的 `install-privileges.ps1` 与界面上的「授予特权」按钮（两者已移除）。
> 需要时按本文手动做一次，一次性操作，之后不用再管。

---

## 1. 为什么需要

只有 **`start` 模式**（在子会话里只跑一个程序）和 **文件剪贴板桥** 需要这两项特权：

| 特权 | Windows 里的名字 | 用在哪 |
| --- | --- | --- |
| `SeTcbPrivilege` | 作为操作系统的一部分 | `WTSQueryUserToken` 拿子会话的登录令牌 |
| `SeAssignPrimaryTokenPrivilege` | 替换进程级令牌 | `CreateProcessAsUser` 用那个令牌起进程 |

代码位置：`internal/rdp/session_launch.go:204-205`（`launchWithWtsToken` 先
`enablePrivilege(seTcbName)` / `enablePrivilege(seAssignPrimaryTokenName)` 再调
`WTSQueryUserToken`）；`internal/rdp/session_launch.go:177-178`（`CreateProcessAsUser`
失败时退回 `CreateProcessWithTokenW`，后者只需 `SeImpersonatePrivilege`）。

**`desktop` 模式（完整第二桌面，走 RDP 连接）不需要这两项**，不授予也能用。
文本剪贴板也不需要（走 RDP 自带 CLIPRDR 重定向）。

没授予时的典型日志（`%LOCALAPPDATA%\LocalRDP\localrdp.log`）：

```
WTSQueryUserToken unavailable: 0x00000522 (客户端没有所需的特权。)
CreateProcessAsUser failed: 0x00000522 (客户端没有所需的特权。)
LaunchInSession failed: no launch method worked
```

## 2. 代价与风险（先读这段）

- 这两项是**高权限**账户权限，`SeTcbPrivilege` 字面意思就是"作为操作系统的一部分"，
  等于让该账户的进程可以完全信任自己。只在你确实要用 `start` 模式时授予。
- 授予是**按账户**写进本机安全策略的（LSA 账户权限），不是按程序，也不是改防火墙 /
  RDP 服务 / 凭据策略。
- **必须注销后重新登录**（或重启）才生效：特权是在登录时写进访问令牌的，已经登录的
  会话不会自己刷新。
- 撤销同样需要重登才彻底生效。

## 3. 做法 A：图形界面（secpol.msc）

1. `Win+R` → 输入 `secpol.msc` → 回车（UAC 确认）。
2. 左侧展开 **安全设置 → 本地策略 → 用户权限分配**。
3. 右侧找到 **作为操作系统的一部分** → 双击 → **添加用户或组** → 输入
   `计算机名\用户名`（或点"高级 → 立即查找"选当前用户）→ 确定。
4. 同样处理 **替换进程级令牌**。
5. 关掉窗口，**注销并重新登录**。

> Windows 家庭版没有 `secpol.msc`，用做法 B。
> 也可以在"本地安全策略"里按英文名找：*Act as part of the operating system* /
> *Replace a process level token*。

## 4. 做法 B：PowerShell 片段（LSA，可复制）

保存为临时 `.ps1`，或用 `pwsh` 交互粘贴运行；脚本会自己提权。

```pwsh
#Requires -Version 7.0
# 给当前用户加/减两项账户权限。用法：.\grant.ps1          （授予）
#                                        .\grant.ps1 -Remove（撤销）
param([switch]$Remove)
$ErrorActionPreference = 'Stop'

$isAdmin = ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()
           ).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)
if (-not $isAdmin) {
    $argList = @('-NoLogo', '-NoProfile', '-ExecutionPolicy', 'Bypass', '-File', "`"$PSCommandPath`"")
    if ($Remove) { $argList += '-Remove' }
    Start-Process pwsh -Verb RunAs -ArgumentList $argList -Wait
    return
}

Add-Type -TypeDefinition @"
using System;
using System.Runtime.InteropServices;
public static class LsaApi {
    [StructLayout(LayoutKind.Sequential)]
    public struct LSA_UNICODE_STRING {
        public ushort Length; public ushort MaximumLength; public IntPtr Buffer;
    }
    [StructLayout(LayoutKind.Sequential)]
    public struct LSA_OBJECT_ATTRIBUTES {
        public int Length; public IntPtr RootDirectory; public IntPtr ObjectName;
        public int Attributes; public IntPtr SecurityDescriptor; public IntPtr SecurityQualityOfService;
    }
    [DllImport("advapi32.dll", SetLastError = true)]
    public static extern uint LsaOpenPolicy(ref LSA_UNICODE_STRING SystemName,
        ref LSA_OBJECT_ATTRIBUTES ObjectAttributes, uint DesiredAccess, out IntPtr PolicyHandle);
    [DllImport("advapi32.dll", SetLastError = true)]
    public static extern uint LsaAddAccountRights(IntPtr PolicyHandle, byte[] AccountSid,
        LSA_UNICODE_STRING[] UserRights, uint CountOfRights);
    [DllImport("advapi32.dll", SetLastError = true)]
    public static extern uint LsaRemoveAccountRights(IntPtr PolicyHandle, byte[] AccountSid,
        bool AllRights, LSA_UNICODE_STRING[] UserRights, uint CountOfRights);
    [DllImport("advapi32.dll")]
    public static extern uint LsaClose(IntPtr PolicyHandle);
    [DllImport("advapi32.dll")]
    public static extern int LsaNtStatusToWinError(uint Status);
}
"@

$rights = @('SeTcbPrivilege', 'SeAssignPrimaryTokenPrivilege')
$me   = [Security.Principal.WindowsIdentity]::GetCurrent()
$sid  = $me.User

function New-LsaString([string]$s) {
    $bytes = [Text.Encoding]::Unicode.GetBytes($s)
    $buf   = [Runtime.InteropServices.Marshal]::AllocHGlobal($bytes.Length)
    [Runtime.InteropServices.Marshal]::Copy($bytes, 0, $buf, $bytes.Length)
    $lsa = New-Object LsaApi+LSA_UNICODE_STRING
    $lsa.Length = [uint16]$bytes.Length
    $lsa.MaximumLength = [uint16]($bytes.Length + 2)
    $lsa.Buffer = $buf
    return $lsa
}

$sidBytes = [byte[]]::new($sid.BinaryLength)
$sid.GetBinaryForm($sidBytes, 0)
$oa = New-Object LsaApi+LSA_OBJECT_ATTRIBUTES
$oa.Length = [Runtime.InteropServices.Marshal]::SizeOf($oa)
$sysName = New-Object LsaApi+LSA_UNICODE_STRING
$policy = [IntPtr]::Zero
# POLICY_CREATE_ACCOUNT (0x10) | POLICY_LOOKUP_NAMES (0x800)
$st = [LsaApi]::LsaOpenPolicy([ref]$sysName, [ref]$oa, 0x00000810, [ref]$policy)
if ($st -ne 0) { throw "LsaOpenPolicy 失败: $([LsaApi]::LsaNtStatusToWinError($st))" }

$lsaRights = @($rights | ForEach-Object { New-LsaString $_ })
if ($Remove) {
    $st = [LsaApi]::LsaRemoveAccountRights($policy, $sidBytes, $false, $lsaRights, [uint32]$lsaRights.Count)
} else {
    $st = [LsaApi]::LsaAddAccountRights($policy, $sidBytes, $lsaRights, [uint32]$lsaRights.Count)
}
$err = [LsaApi]::LsaNtStatusToWinError($st)
[void][LsaApi]::LsaClose($policy)
if ($st -ne 0) { throw ('Lsa 操作失败 ntstatus=0x{0:X8} win32={1}' -f $st, $err) }

Write-Host ''
Write-Host ("  {0} -> {1}" -f ($(if ($Remove) { '已移除' } else { '已授予' })), $me.Name) -ForegroundColor Green
$rights | ForEach-Object { Write-Host "    · $_" }
Write-Host ''
Write-Host '  注意：特权写进的是"登录时生成的令牌"，当前会话不会自动生效。' -ForegroundColor Yellow
Write-Host '        请注销后重新登录（或重启）一次。' -ForegroundColor Yellow
```

运行完输出「已授予 -> 计算机名\用户名」即可，然后**注销重登**。

## 5. 验证

```pwsh
whoami /priv | Select-String 'SeTcb|SeAssignPrimaryToken'
```

期望两行都在（状态一般是"已启用"/`Enabled`；显示"已禁用"也说明账户已有该权限，
程序运行时会自己 `AdjustTokenPrivileges` 打开）。

看本机策略里到底写了谁：

```pwsh
secedit /export /areas USER_RIGHTS /cfg "$env:TEMP\ur.inf"
Select-String -Path "$env:TEMP\ur.inf" -Pattern 'SeTcbPrivilege|SeAssignPrimaryTokenPrivilege'
```

`SeTcbPrivilege = *S-1-5-21-...` 里包含你账户的 SID 即已写入。

## 6. 撤销

- 做法 A 反过来：`secpol.msc` → 用户权限分配 → 那两个策略 → 选中用户 → 删除。
- 做法 B：同一段脚本加 `-Remove` 再运行一次。
- 撤销后同样**注销重登**，否则当前令牌里仍然带着特权。

## 7. 常见疑问

- **为什么界面里看不到"授予特权"了？** 这项能力从程序里去掉了，避免一个常驻 GUI
  随手改安全策略；要 `start` 模式就按本文手动做一次。
- **重登后 `whoami /priv` 还是没这两行？** 多半是账户被域策略/本地策略重置覆盖，
  或者授予时用的不是同一个账户（注意 `计算机名\用户名` 与微软账户 `MicrosoftAccount\…` 的区别）。
- **只想要第二桌面？** 用 `desktop`，本文整篇都可以跳过。
